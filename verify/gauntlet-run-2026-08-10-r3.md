# Gauntlet run — Sophos free-model onboarding

Date: 2026-08-10 20:27 EDT

## Goal

Improve first-run onboarding for a non-technical user connecting the free
Ollama Cloud model, guide prerequisites, and prove the first DeepSeek V4 Flash
0731 chat through the real daemon without manual configuration-file editing.

## Bar

A new user sees the free-model path on the first screen, can see Node/daemon/
bridge/kernel health, and can send a real first prompt to
`ollama-cloud/deepseek-v4-flash:0731-cloud` in under three minutes, with the
existing tests and safety controls preserved.

## Diagnosis gate

- **Symptom:** The previous first-run strip was generic ("connect a provider")
  and disappeared as soon as any provider was connected. It did not show
  daemon prerequisites or prevent a first prompt while the real kernel/bridge
  was still booting.
- **Authoritative surfaces:** `FirstRunBanner`, `ChatView`/`Composer`, the
  provider catalog, Rust `get_engine_status`, and the bridge's live
  `getRuntimeInfo`/model selection path.
- **Reproduction:** Start a fresh Tauri session with no provider; the banner
  offered only a generic provider setup action. Connect a provider while the
  daemon was still starting; no Node/daemon/bridge/kernel checklist was shown.
- **Owner/boundary:** Frontend onboarding owns the user-facing guide and prompt
  gate; Rust owns process health; bridge/daemon own model and kernel truth.
- **Unknowns:** OAuth/API-key availability depends on the operator account;
  the kernel capability can be configured before a cell has executed. This run
  does not claim that a provider credential was invented or that the kernel is
  a security sandbox.
- **Non-goals:** No automatic credential generation, no paid provider fallback,
  no unbounded autonomous run, and no changes to run-guard/refinement-gate/
  kernel-dead safety controls.
- **Acceptance evidence:** First-screen checklist, explicit DeepSeek starter
  copy, composer gate in Tauri, live daemon default-model proof, and 37/37
  browser E2E plus native/bridge builds.

## Pieces

1. **Guided first-run surface** — add free DeepSeek discovery, live prerequisite
   checklist, refresh/setup actions, and browser-preview disclosure.
2. **First-chat readiness** — gate the Tauri composer until managed Node,
   daemon, bridge, kernel, provider, and model checks are ready; preserve the
   browser demo behavior.
3. **Provider discovery and verification** — make Ollama Cloud's free starter
   model explicit and verify default model selection without config editing.
4. **Verification** — add onboarding assertions to the standing browser suite
   and live daemon harness; retain existing safety and process gates.

## Implementation

- `FirstRunBanner` now owns `useOnboardingStatus`, polling Rust engine process
  status plus bridge runtime/provider/model state. It renders Node runtime,
  daemon, bridge, kernel, and free model indicators.
- The first-run copy names `DeepSeek V4 Flash 0731` and routes
  `Connect free DeepSeek` to the existing in-app Providers screen. No settings
  file editing is required; the existing bridge `applyDefaultModel` selects the
  free model on connection.
- The Tauri composer is disabled until the checklist is green, while browser
  preview remains usable and explicitly labeled as preview.
- Ollama Cloud's provider card now explains the free starter path and automatic
  model selection.
- The browser Chat view test asserts the first-screen checklist and DeepSeek
  copy without changing the standing test count.
- The live harness asserts bridge reachability, default model selection, live
  catalog presence, and a real assistant response from the first prompt.
